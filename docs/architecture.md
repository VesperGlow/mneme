# 架构与一致性

## Rust 模块

| 模块 | 职责 |
|---|---|
| `api` | 鉴权、SSE、会话并发 |
| `chat` / `settings` | 人格与上下文预算、即时性格设置、WebUI 密码会话、事务重置与图谱清理 |
| `continuity` | 有界历史、滚动摘要、压缩进度与提取任务原子提交 |
| `store` | SQLite 事务、对话状态机、记忆版本、持久化任务 |
| `llm` | 外部 Chat Completions、分片 SSE 解析、严格提取 JSON |
| `models` | 本地模型协议、维度/数值校验、超时 |
| `tools` / `assets` | 工具 HTTP 客户端、调用审计、截图与图片附件、多模态消息和会话归属校验 |
| `graph` | 参数化 Cypher、索引初始化、幂等投影、三路召回 |
| `memory` | 候选校验、RRF、精排、时间衰减、后台工作循环 |
| `domain` / `config` | 数据结构、稳定标识和配置边界 |
| `console` / `console_store` | 内嵌 WebUI、统计、过滤分页、人工记忆写入、修订历史和删除保护 |
| `telemetry` | 不含原始内容的进程内请求次数、失败数与耗时 |

服务使用 Tokio + Axum、reqwest/rustls、SQLx SQLite，不依赖编译期数据库。数据库迁移随二进制打包。SQLite 驱动在线程中处理 I/O，业务不会把同步 SQLite 连接锁持有在异步请求中。

## 对话与任务事务

QQ、API 和 WebUI 始终使用 `metadata[conversation.id]` 指向的持久对话。旧 API 和 QQ 会话、消息、图片、投递队列与工具记录在启动时原子合并，保留别名；`turns.channel` 保留消息渠道，所有渠道共用生成锁。

`begin_turn` 在 `BEGIN IMMEDIATE` 内检查幂等 ID 和会话状态，持久化用户消息并设置会话锁。回复完成后，一个事务写入助手消息、完成状态、释放会话锁并累计用户/助手原文 Token；达到默认 2048 tokens 后插入一个 `extract:batch:<seq>` 任务并推进持久游标。提取以批次原始用户消息为证据，来源校验和所有候选落库与任务确认在同一事务提交；旧版本单消息任务继续兼容。出现错误则保留原用户消息并标记失败，失败轮不进入生成历史与自动记忆。

任务用原子 `UPDATE ... RETURNING` 领取，状态为 pending → running → 删除，失败后指数退避（最多 900 秒），默认 8 次转 dead。启动恢复所有 running 任务；提取结果与提取任务确认在同一事务中提交。图谱任务 ID 带记忆 revision，更新和旧版本移除不会丢失唤醒。

Neo4j 投影为至少一次投递，使用 MERGE 和按 ID 删除保证幂等。任务始终读取 SQLite 当前状态；遗忘与投影同时发生时，短暂旧投影仍可能写入，但 SQLite 在检索出口再次检查有效状态，新 revision 的删除任务最终清理投影。相同数据库只能启动一个 Mneme 进程，由文件锁约束。

## 数据表

- `sessions`：会话创建时间及当前生成轮次。
- `turns`：幂等 ID、状态、完成时间和不含原文的错误码。
- `messages`：原始 UTF-8 对话，递增 seq 提供可靠观察顺序。
- `assets` / `message_assets`：规范化 JPEG、会话归属和消息图片顺序；图片顺序参与请求幂等校验。
- `tool_calls`：工具调用状态、经过筛选的参数摘要、有界网页结果、错误码和耗时；中断调用在恢复时标记失败。
- `memories`：属性键 slot、规范内容、哈希、种类、重要性、置信度、实体、持久化向量、版本状态、观察序号、有效期与访问统计。一个 slot 和一个内容哈希各自最多对应一条 active 记忆。
- `memory_sources`：记忆到用户消息的多对多证据，包含原文引文和观察时间。
- `jobs`：可恢复的提取队列与投影 outbox。
- `forget_barriers`：手动遗忘以当前已接收消息为边界；自动衰减只保护至旧记忆的观察位置，允许排队中的较新确认。衰减更新比较 revision，避免遗忘并发更新后的新值。
- `metadata`：模型选型缓存、WebUI 性格覆盖、密码哈希、QQ 账号归属及待执行的图谱清理标记。同时保存 API 持续对话 ID。
- `conversation_context` / `conversation_aliases`：每段对话的摘要、已压缩游标和次数，以及旧 API 窗口到持续对话的映射。
- `console_sessions`：登录凭证哈希及滚动过期时间；登录 Cookie 和服务端记录均跨重启保留。
- `extracted_messages`：已完成提取的用户消息；防止压缩补队列或重试重复加强记忆。
- `memory_revisions`：由同一 SQLite 事务内的触发器记录新增/修订快照；迁移为旧数据建立初始快照。
- `content_barriers` / `suppressed_sources`：人工编辑和删除时屏蔽旧内容及其原始消息，阻止旧提取任务绕过属性键保护。

Console 使用密码登录 Cookie；终端集成继续使用 Bearer API，静态资源编译进二进制。人工编辑采用 revision 比较，来源保持可追溯；人工新增没有伪造的对话消息。正文变化时清空旧向量并排队重建，向量写回和索引完成标记都检查当前版本。`deleted_at` 是不可由后台工作恢复的逻辑墓碑，删除与内容修改的接口细节见 [Console 文档](console.md)。

同一个 slot 更新时旧记忆变成 superseded，并通过 superseded_by 指向新版本；原证据仍留在原版本。等价事实保留同一记忆 ID，追加来源并提高观察时间/置信度。LLM 可以合并真正的同义表达，但仍需来源和稳定键约束；不做仅凭高向量相似度的自动合并，避免把否定或数值变化混为一谈。

## 检索与时间

1. 原问题与最多三个保留原问题上下文的子问题分别经 Qwen3 编码，文档不带查询指令。固定 1024 维与 L2 归一化不变。
2. 并行获取 Neo4j CJK 全文、实体及 SQLite 近期事实；各分面各自 ANN 后合并。SQLite 最近 256 条补检未投影事实，投影只返回 ID，现态和权限仍从 SQLite 读取。
3. RRF 融合后，最多六个有效种子执行两层共享实体扩展；最短可用桥接路径随目标事实进入精排。路径、候选和最终结果均有界，弱路径不会仅凭图连接自动注入。
4. 所有有效候选先精排，避免低 cosine 提前丢弃语义改写。每个分面使用绝对 0.1 和相对 0.8 门槛；最终还须满足 cosine 0.4 或强精排补救 0.6。精排失败返回降级空结果。默认最终排序权重仍是 0.8 精排、0.1 RRF、0.1 强度。
5. 最多返回六条、4000 tokens 的长期记忆，必要桥接事实一起占用预算；返回前及慢速压缩后复核 revision/删除/有效期。历史压缩预算 100000 tokens，摘要上限 2000 tokens，不按轮数截断。
6. 提取独立按 2048 tokens 或 120 秒等待时限排队，每组最多四个原始来源。部分有效结果可以落库，但失败来源不确认；重试同一来源/事实不重复强化。属性归并保留键别名，序号、事务、遗忘屏障与投影重读维持一致性。

统一计量在 `tokens.rs`、`usage.rs`：所有物理模型请求共享 `model_requests` 账本；CPU 服务返回固定模型的实际分词数。API 原值、估算、来源与字段覆盖分开保存。后端计算单轮/会话累计，SSE `usage` 替换快照、`turn_usage` 返回本轮累计；上下文分布独立于累计消耗。原生 tokenizer JSON 可配置，未知词表明确回退；图片及封装仍为估算。
`strength = importance * confidence * 2^(-elapsed_days / (half_life_days*(0.5+2*importance)))`，默认半衰期参数 180 天。importance=0.8 的事实有效半衰期为 378 天；importance=0.4 为 234 天。默认 strength < 0.12 时逻辑遗忘。LLM 的原始观察时间用于年龄，不以系统重建/重试时间伪装成新事实。

检索有独立的 8 秒总预算，包含 SQLite 连接等待、查询、模型和图查询；子阶段也有限时。整体超时返回空记忆和降级状态，数据库本身另有 busy_timeout 约束。对话生成、记忆提取和投影互不持有跨网络的数据库事务。

## 模型运行时与扩展

`mneme-tools` 是现有 `mneme.pod` 内新增的独立容器，经鉴权 HTTP `127.0.0.1:8091` 与 Rust 通信。Rust 解析完整的 LLM 工具调用流并逐步执行，网页内容标记为不可信，结果和来源继续交给原有 LLM；截图以多模态消息发送。网页工具不写入用户记忆来源。`mneme-models` 和 Neo4j 保持现有协议与职责。

工具故障不影响原有核心服务的启动。每轮调用、上下文、浏览器会话与资源均设上限；重置同时删除图片和调用记录，通过持久化待清理标记关闭浏览器上下文。共享 Pod 的网络隔离限制及 CDP/SSRF 防护见 [工具服务文档](tools.md)。

Python 服务只承担预训练模型推理。CPU FP32 的兼容性更稳定，不要求 AVX512、BF16、CUDA 或 xformers。推理队列最多 16 个等待请求，超载返回 429；Rust 层任务会重试或降级。请求断连后取消未开始的推理；已经运行的 CPU 推理无法抢占。查询与精排优先于文档。提取复用外部聊天 LLM，没有独立的小模型判定阶段。Embedding 客户端对批内重复文本去重并按最多 8 条分块，等价或完全重复的已知事实可复用现有向量；同一当前版本已完成的重复投影任务直接确认，显式重建仍强制执行。

Rust 模型客户端对完整输入哈希建立最多各 128 项、5 分钟有效的成功结果缓存，并共享同输入的进行中请求；查询/文档编码分别建键，精排键包含问题和全部候选正文，编辑后重新评分。失败不缓存。每个 App 独立持有缓存，不跨个人实例共享。模型服务 `/health` 额外返回推理完成、失败、队列拒绝、取消计数和累计排队/推理耗时，便于区分模型计算与队列等待。

未来反思/主动行为可以新增独立持久化 job kind 和对应迁移，经同一来源/置信度规则写入记忆；关系演化建议单独建关系状态表，不让模型直接覆写人格配置。人格变化应记录版本、理由和来源，并通过显式策略批准。多用户支持必须为所有数据库记录、向量索引召回与图扩展增加统一 owner 隔离；当前不提供此能力。

## QQ 适配

QQ 接收器在同一 Axum 进程内独立监听 8081，只提供 `/qqbot`。通过签名和时间窗校验后，在 SQLite 事务中自动建立首个私聊账号、消息去重、会话映射和 inbox；落库后立即 ACK。独立协程按顺序消费，调用与 HTTP 共用的 `chat` 生成模块，再从持久化回复投递 QQ。HTTP SSE 不受 QQ 平台响应延迟影响。

`qq_inbox` 保留接收序号、原消息 ID、会话、状态、生成结果和分段发送进度。回复崩溃恢复优先复用已有 turn，网络重试不会再次生成。`qq_sessions` 持久保存当前会话；首条私聊自动确定个人账号，后续沿用，旧版已保存的账号保持兼容。Console 的遗忘屏障同时覆盖已接收但未生成的 QQ 输入。

自动模型选择结果按提供商地址缓存于 SQLite，重启可继续使用已有型号，不依赖模型目录即时可用。明确配置 `MNEME_LLM_MODEL` 时绕过发现与缓存。

## 真实模型评估后的记忆校验（2026-10-18）

提取与记忆资格判断仍在同一次生成模型调用内完成，没有另设生产前置判定服务。当前原话是唯一证据，历史索引只用于选择稳定属性键。键只描述主体和属性维度，不能随属性值变化；即使历史键包含旧值，也要求沿用已有同属性键。人物的姓名、地点和职业分别使用属性键。逐项校验候选，孤立的坏字段、旧引用和不存在的来源不再使其他独立有效候选一起失败；非空响应全部无效时保留失败与重试语义。

批处理中，若某来源的候选全部无效，该来源不会被写入提取完成回执；有效来源提交、原批任务确认和这些来源的独立重试入队处于同一 SQLite 事务。独立重试沿用现有次数与退避上限，不无限生成新任务。已完成来源的重复单消息任务在模型调用前确认退出。一个来源已有部分有效候选时仍提交有效项，该来源剩余漏项不保证自动补齐。

提取历史参考从近期 256 项与向量索引候选中按当前原话筛选最多 24 项，受原有上下文预算限制。写入前候选与逐字引用至少达到 `memory.evidence_min_score`（默认 0.5）；长引用按约 256 tokens、192 tokens 步长分窗，降低截断丢失后半段证据的风险。该门槛只过滤语义无关内容，不能证明否定或数值的逻辑蕴含。等价 ID 不符合当前槽位及规范内容时忽略该提示，继续独立校验当前事实，不把旧内容替换进新候选。

支持结构化输出的生成服务可开启 `llm.json_schema`，默认关闭以兼容现有提供方。Schema 的来源 ID 和等价 ID 均来自当前实际数据，不包含测试答案；优先生成原文引用，模型仍须通过相同运行时校验。检索保留绝对 cosine/精排门槛，并用 `memory.rerank_relative_min=0.8` 去掉明显弱于最相关候选的尾部，设为 0 可关闭相对门槛。调试超时额外提供最后阶段名称，保留原有降级与总预算行为。

CPU 模型服务新增可选精度环境变量 `MNEME_CPU_DTYPE`（Embedding）和 `MNEME_CPU_RERANK_DTYPE`（Reranker），均默认 `float32`。支持 BF16 的 CPU 可显式选择 Embedding `bfloat16`，Reranker 保持 `float32`；健康检查报告两种精度。向量归一化始终以 FP32 运算。全 BF16 的精排在实际边界样本中改变了筛选结果，因此不设为默认。模型客户端不保留空闲 HTTP 连接，避免将已失去上游的复用连接一直等到模型超时；成功结果缓存与同输入请求合并继续有效。

FastAPI 完成请求体解析后，断连监听直接等待 ASGI `http.disconnect`。不轮询 Starlette 的 `is_disconnected()`：其内部取消作用域可能吞掉任务取消，使已完成推理的响应卡在清理阶段。真实断连仍取消排队项；正在运行的 CPU 任务仍不可抢占。

逐项测试记录、精度比较、失败案例与适用限制见 [真实模型报告](reports/memory-e2e-2026-10-18.md)。这些变更不自动迁移或改写生产向量，也不把单人应用的不同会话当作不同用户。
