# 架构与一致性

## Rust 模块

| 模块 | 职责 |
|---|---|
| `api` | 鉴权、SSE、会话并发、人格与上下文预算 |
| `store` | SQLite 事务、对话状态机、记忆版本、持久化任务 |
| `llm` | 外部 Chat Completions、分片 SSE 解析、严格提取 JSON |
| `models` | 本地模型协议、维度/数值校验、超时 |
| `graph` | 参数化 Cypher、索引初始化、幂等投影、三路召回 |
| `memory` | 候选校验、RRF、精排、时间衰减、后台工作循环 |
| `domain` / `config` | 数据结构、稳定标识和配置边界 |
| `console` / `console_store` | 内嵌 WebUI、统计、过滤分页、人工记忆写入、修订历史和删除保护 |
| `telemetry` | 不含原始内容的进程内请求次数、失败数与耗时 |

服务使用 Tokio + Axum、reqwest/rustls、SQLx SQLite，不依赖编译期数据库。数据库迁移随二进制打包。SQLite 驱动在线程中处理 I/O，业务不会把同步 SQLite 连接锁持有在异步请求中。

## 对话与任务事务

`begin_turn` 在 `BEGIN IMMEDIATE` 内检查幂等 ID 和会话状态，持久化用户消息并设置会话锁。回复完成后，一个事务写入助手消息、完成状态、释放会话锁并插入 `extract:<turn_id>` 任务。出现错误则保留原用户消息并标记失败，失败轮不进入生成历史与自动记忆。

任务用原子 `UPDATE ... RETURNING` 领取，状态为 pending → running → 删除，失败后指数退避（最多 900 秒），默认 8 次转 dead。启动恢复所有 running 任务；提取结果与提取任务确认在同一事务中提交。图谱任务 ID 带记忆 revision，更新和旧版本移除不会丢失唤醒。

Neo4j 投影为至少一次投递，使用 MERGE 和按 ID 删除保证幂等。任务始终读取 SQLite 当前状态；遗忘与投影同时发生时，短暂旧投影仍可能写入，但 SQLite 在检索出口再次检查有效状态，新 revision 的删除任务最终清理投影。相同数据库只能启动一个 Mneme 进程，由文件锁约束。

## 数据表

- `sessions`：会话创建时间及当前生成轮次。
- `turns`：幂等 ID、状态、完成时间和不含原文的错误码。
- `messages`：原始 UTF-8 对话，递增 seq 提供可靠观察顺序。
- `memories`：属性键 slot、规范内容、哈希、种类、重要性、置信度、实体、持久化向量、版本状态、观察序号、有效期与访问统计。一个 slot 和一个内容哈希各自最多对应一条 active 记忆。
- `memory_sources`：记忆到用户消息的多对多证据，包含原文引文和观察时间。
- `jobs`：可恢复的提取队列与投影 outbox。
- `forget_barriers`：手动/衰减遗忘时记录已观察消息的最高序号，阻止旧提取任务复活该 slot。
- `metadata`：未来迁移和行为模块的格式元数据预留。
- `memory_revisions`：由同一 SQLite 事务内的触发器记录新增/修订快照；迁移为旧数据建立初始快照。
- `content_barriers` / `suppressed_sources`：人工编辑和删除时屏蔽旧内容及其原始消息，阻止旧提取任务绕过属性键保护。

Console 复用 Bearer API，静态资源编译进二进制。人工编辑采用 revision 比较，来源保持可追溯；人工新增没有伪造的对话消息。正文变化时清空旧向量并排队重建，向量写回和索引完成标记都检查当前版本。`deleted_at` 是不可由后台工作恢复的逻辑墓碑，删除与内容修改的接口细节见 [Console 文档](console.md)。

同一个 slot 更新时旧记忆变成 superseded，并通过 superseded_by 指向新版本；原证据仍留在原版本。等价事实保留同一记忆 ID，追加来源并提高观察时间/置信度。LLM 可以合并真正的同义表达，但仍需来源和稳定键约束；不做仅凭高向量相似度的自动合并，避免把否定或数值变化混为一谈。

## 检索与时间

1. 当前问题经带任务指令的 Qwen3 编码，文档不带该指令。左填充取最后有效 token，L2 归一化，固定 1024 维。
2. Neo4j `ActiveMemory` 标签上执行 HNSW cosine、CJK 全文和实体名直接命中。中文查询拆成双字 OR 词，所有用户输入转为受限字面值，不接受原始 Lucene 表达式。
3. 同时为最多 256 条最近有效 SQLite 记忆计算向量内积与中文双字重叠，补齐未投影内容和服务故障窗口。最多 6 个种子经共享实体扩展两跳邻居。
4. 每个通道按排名用 `1/(60+rank)` 做 RRF，取最多 32 条候选；逐条从 SQLite 读取现态，过滤失效内容。
5. GTE 对问题/记忆对评分，默认丢弃 sigmoid 分数低于 0.1 的内容。最终分数为 `0.8*rerank + 0.1*min(12*RRF,1) + 0.1*strength`；分数阈值应按自己的中文数据校准。
6. 最多返回 6 条、4000 字符的长期记忆上下文。历史保留完整用户/助手对，按最新向前选择，避免半个对话轮。默认整体上下文字符预算为 16000，适合较小的外部模型窗口；它是保守字符预算，不是精确 tokenizer 计数。

`strength = importance * confidence * 2^(-elapsed_days / (half_life_days*(0.5+2*importance)))`，默认半衰期参数 180 天。importance=0.8 的事实有效半衰期为 378 天；importance=0.4 为 234 天。默认 strength < 0.12 时逻辑遗忘。LLM 的原始观察时间用于年龄，不以系统重建/重试时间伪装成新事实。

检索有独立的 8 秒总模型等待预算，子阶段也有限时；精排超时保留 RRF 顺序。SQLite 查询另受数据库 busy_timeout 约束。对话生成、记忆提取和投影互不持有跨网络的数据库事务。

## 模型运行时与扩展

Python 服务只承担预训练模型推理。CPU FP32 的兼容性更稳定，不要求 AVX512、BF16、CUDA 或 xformers。推理队列最多 16 个等待请求，超载返回 429；Rust 层任务会重试或降级。查询与精排优先于文档，但无法抢占正在执行的推理请求。

未来反思/主动行为可以新增独立持久化 job kind 和对应迁移，经同一来源/置信度规则写入记忆；关系演化建议单独建关系状态表，不让模型直接覆写人格配置。人格变化应记录版本、理由和来源，并通过显式策略批准。多用户支持必须为所有数据库记录、向量索引召回与图扩展增加统一 owner 隔离；当前不提供此能力。

## QQ 适配

QQ 接收器在同一 Axum 进程内独立监听 8081，只提供 `/qqbot`。通过签名和时间窗校验后，在 SQLite 事务中处理本人绑定、消息去重、会话映射和 inbox；落库后立即 ACK。独立协程按顺序消费，调用与 HTTP 共用的 `chat` 生成模块，再从持久化回复投递 QQ。HTTP SSE 不受 QQ 平台响应延迟影响。

`qq_inbox` 保留接收序号、原消息 ID、会话、状态、生成结果和分段发送进度。回复崩溃恢复优先复用已有 turn，网络重试不会再次生成。`qq_sessions` 持久保存当前会话；绑定只允许带一次性证明的本人。Console 的遗忘屏障同时覆盖已接收但未生成的 QQ 输入。

自动模型选择结果按提供商地址缓存于 SQLite，重启可继续使用已有型号，不依赖模型目录即时可用。明确配置 `MNEME_LLM_MODEL` 时绕过发现与缓存。
