场景 knowledge，第 1 轮

用户：Python 函数的默认列表参数为什么会累积？给一个简短正确的修改例子。

基线原文：

默认参数在**函数定义时**就求值一次，那个列表只创建一次，之后挂在函数对象的 `__defaults__` 上；每次调用时，如果没有传入参数，拿到的都是同一个列表，所以它会被一直累积下去。这不是 Python 的 bug，规则本来就是这样的。

改法是把它当作哨兵值（用来表示“没传参数”的标记）：

```python
def add(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
```

调用 `add(1)` 和 `add(2)` 现在会各得 `[1]`、`[2]`。注意，不要为了“省一行”就写 `bucket = bucket or []`，因为空列表传进来时会被换掉，语义就错了。

……另外，如果你本来就想要累积效果，用可变默认值其实也行，只是容易被别人当成错误。这种写法最好加注释说明意图。

精简后原文：

默认参数在 `def` 执行那次就被求值了，只求值一次，然后绑在函数对象上。所以那个 `[]` 不是每次调用新建的，是同一个列表被反复用——`append` 当然越积越多。不是 Python 的 bug，是定义时求值这个规则。

改法：用 `None` 当哨兵，函数里再建列表。

```python
def append_item(item, lst=None):
    if lst is None:
        lst = []
    lst.append(item)
    return lst
```

这样每次不传 `lst` 都拿到新列表。要是 `None` 本身也是合法输入，就换个专属哨兵：

```python
_SENTINEL = object()

def append_item(item, lst=_SENTINEL):
    if lst is _SENTINEL:
        lst = []
    lst.append(item)
    return lst
```

场景 probe，第 5 轮

用户：问个正经的，Python 默认列表参数为什么越调用越长？简单说。

基线原文：

因为默认参数在函数定义时只求值一次，那个列表从头到尾就只有一个，每次调用改的都是同一个。

要可变默认值，就写 `None`，进函数再判一下新建列表。

精简后原文：

因为默认参数只在函数定义时求值一次，不是每次调用都重新建。

```python
def f(x, lst=[]):   # 这个 [] 在 def 执行时就创建了，之后一直复用
    lst.append(x)
    return lst
```

每次调用没传 `lst` 时，用的都是同一个列表对象，所以越攒越多。正确写法是用 `None` 当占位：

```python
def f(x, lst=None):
    if lst is None:
        lst = []
    lst.append(x)
    return lst
```

坑在于可变默认值（list、dict、set 都算）会被共享，不可变的（数字、字符串、None）没事。
