# Mneme 记忆与统一 Token 计量验证（2026-10-19）

本轮已完成代码、迁移、计量与回归验证，但**记忆质量验收尚未全部达标**。最终同版本的71条来源、46个问题汇总中，逐来源提取精确率/召回率均为100%，检索精确率94.1%、召回率82.4%，最终状态保留30/31条应有事实。独立盲测暴露了兼容事实误覆盖与语义改写漏召回；这些失败保留在结果中，没有通过改金标或放宽门槛隐藏。

本轮保留 Rust/Axum、SQLite 事实源、Neo4j 投影、本地 Embedding/Reranker 与兼容 Chat Completions 架构。未部署生产，未读取或修改生产记忆。测试使用临时 SQLite、独立 Neo4j、固定离线 CPU 权重，以及官方 `deepseek-flash`；真实 API 凭证仅在测试中继内存中使用，没有写入代码或报告。

## 修改与依据

- **混合召回**：修复所有通道被 cosine 提前截断的问题。RRF 后的有效候选先经过精排；低 cosine 的语义改写必须满足更强的精排补救阈值。复合问题使用原问题及最多三个保留原问题上下文的分面，分别取 ANN 候选、计算相对精排门槛。单独拆开代词会召回错误主体，已通过真实 GTE 探测验证并改为保留指代上下文。两层共享实体扩展可保留桥接事实，整条路径一起检查版本、时效和预算。
- **事实更新**：相关旧属性参考由“最近64条中取8条”扩大为“近期256条与向量索引中取最多24条”。`attribute_of` 提供同主体同属性映射，规范等价确认仍保留严格内容检查；精确重复归并后持久保存键别名，后续更正不会另留一个旧值。重复确认合并实体、保留仍有效的期限；同一来源的重试不重复强化。
- **证据检查**：模型只引用“是个儿科医生”而省略人物时，完整关系事实与残缺引文的向量相似度过低，会错误拒收。现在仅对显著短于事实的连续引文，扩展到原文中包含它的完整句子，再进行原有校验；扩展有256 Token上限，仍不能引用其他来源。该修复使冻结盲测的医生职业来源从重试耗尽恢复为成功处理。
- **异步一致性**：来源按数据库序号处理，同一批不同来源可顺序更新同一属性。部分失败先提交有效事实，不给未完整来源写完成回执；有界重试继续补提取。每组最多四个来源，分组之间传递有 Token 上限的已验证属性键索引。保留事务、序号新旧判断、人工编辑/遗忘屏障、来源屏蔽、版本校验与投影重读。检索/推理取消后将请求标为 interrupted，迟到的 running 快照不能恢复该状态。
- **及时提取**：默认改为累计2048个原文 Token；未达阈值的短对话在等待120秒后的后台调度中排队。等待阈值是调度条件，处理延迟还包括工作协程可用性、模型队列与重试，不能作为硬实时 SLA。水位沿用原始消息序号，跨重启不丢失；压缩不推进提取水位。
- **自然回忆**：精排后及慢速压缩后核查事实版本；上下文装配再次排除失效记忆。系统规则区分人物、时序与当前纠正，逐项回答复合问题；不因一项未知否认全部已知事实，不从关系连接补造属性。提取提示要求当前值，不把旧值比较当成当前事实正文。

## Token 契约

所有物理模型请求共享 `model_requests`，用途覆盖聊天和工具循环、压缩、提取、表情理解、Embedding、Reranker。模型目录/健康检查和浏览器执行本身不是模型推理，不计入模型 Token。

1. `usage.input_tokens/output_tokens/...` 只保留 API 或本地模型服务返回的计数；推理是输出子项，缓存命中/写入是输入子项，不重复相加。总量优先使用供应商总量，缺失时可由已返回的输入/输出推导。
2. `usage.estimated` 单独记录缺失字段的估算、分词器、模型匹配情况及输出是否只有已观测下限。未知隐藏推理不伪造为零；失败或取消的请求可能只有输入估算与已收到的实际字段。
3. 累计保留实测合计和 `reported` 覆盖次数；`effective` 用实测优先补缺，`estimated` 给出使用估算的次数。实测与估算混合显示时带“≈”，显示各自覆盖次数和实测合计。没有完整数据的历史消耗无法补录为真实值。
4. 流式重复 usage 替换同一请求；重放不新增请求；客户端缓存命中或共享同一次在途推理不重复记账。单轮与会话聚合均由后端计算。跨来源批次归属于该批最后一个来源轮次，会话账本只计一次。
5. 当前上下文独立估算系统、摘要、记忆、历史、当前消息、工具定义/参数/结果/图片、实际回传推理与封装。回复预留独立列出。累计推理消耗不自动成为下一轮上下文。
6. 已知 tiktoken 模型自动选词表；其他模型可配置本地 `tokenizer.json`。未知模型回退 o200k 时明确标记 `model_matched=false`，不是原生词表或 API 实测。官方 DeepSeek Tokenizer 已单独实际加载验证；生产不会自动下载。图片和消息封装仍是估算。CPU 服务使用固定模型原生 Tokenizer 的 attention mask 统计截断后非填充 Token，包含查询指令、每个精排对的查询和缓存分项。

原生分词不等于精确计费：供应商消息封装、图片、隐藏推理可能不同，最终以 API usage 为准。[DeepSeek Token 文档](https://api-docs.deepseek.com/quick_start/token_usage/)、[Transformers Tokenizer 文档](https://huggingface.co/docs/transformers/main_classes/tokenizer)。密码、传输体积和数据字段的存储长度校验仍可使用字符/字节；它们不是模型上下文或消耗计量。

新配置为 `llm.summary_tokens`、`memory.context_tokens`、`memory.extract_every_tokens`、`memory.extract_max_delay_seconds`；旧字符 TOML 字段接受为数值别名，建议迁移到新名称。安装脚本改写新的 Token 环境变量。迁移0010保留旧用量记录并扩展用途，新增属性键别名表；没有重写原始消息或旧证据。

## 测试方法与边界

修复前冻结 Git 起点的 E2E 二进制，分别运行36轮/20问主集和13轮/8问新主题集。最终版本在同一模型、temperature=0、关闭 thinking、相同 FP32 本地模型下执行主集、新主题、展馆确认集及独立盲测。金标没有因结果改写。供应商别名不能固定私有权重，网络和负载也存在波动，不能把小样本差异当作普遍加速倍数。

三套盲测均由单独 DeepSeek 请求编写；出题请求没有读取实现、先前结果或开发样例。应用只收到原话/问题，不收到金标。各套首次完整结果单独报告；第一套后来用于诊断与回归，重跑不再称为新盲测。第三套出题前明确告知固定的隐私策略，避免把正确拒存健康/身份资料误判为漏提取。它们是同供应商模型独立出题的留出测试，不是外部人工验收，也不能代表任意真实用户分布。

常规 Rust **97项通过**，10项默认忽略；其中需要真实依赖的测试另外执行了官方 Tokenizer、完整链、批提取、无依据个人问题和配对检索。Python宿主37项通过，8项依赖测试在模型容器中执行：队列6项、实际 Tokenizer计量2项均通过。Node实际沙箱 Chromium 与工具测试15/15通过；WebUI实际 Chromium桌面/手机、流式思考、Token合计、刷新、幂等、权限、记忆管理、设置、XSS与重置通过。严格Clippy、rustfmt、语法与diff检查通过。Rust测试使用关闭调试信息、关闭增量编译的配置；最后一次默认调试配置复跑曾遇到磁盘不足，清理该次生成的构建产物后按同一低磁盘配置重新完成。

## 异步、用量与自然回忆核验

真实自动批提取用200 Token测试阈值缩短等待，两个会话各12条来源，分别自动产生2和4个提取任务。完成后各12/12回执、6/6当前事实、0额外事实、0死任务，处理耗时约19.0秒和11.3秒；时间包含本地CPU与网络，不是默认120秒到期的硬时限。低于阈值的超时排队、重启水位、部分失败重试、重复确认不重复强化、属性键别名后续替换由确定性回归另行覆盖。

逐来源原始RPC usage与持久账本对账覆盖237条来源、601次提取及来源/证据Embedding物理请求，无不一致；没有把重复汇总的数据再次计数。主SSE、查询Reranker、Agent工具循环未列入这份逐来源独立对账，其字段解析、物理请求数、原生Token、缓存合并、取消、后端轮次聚合和UI展示分别由协议、模型与浏览器测试验证。

另用真实模型询问无证据的工作、城市、亲属三个问题，均明确未知，没有猜出私人属性。一个早期版本在无召回时编造“杭州产品经理”，现已加入逐项个人事实证据规则，最终核心集相同场景不再捏造。不能据此声称所有幻觉已消除。

## 延迟与未采用的实验

修复前主集检索P50/P95约435/598毫秒；最终核心集约852/2865毫秒。扩大候选、复合问题多次精排和关系路径检查增加CPU耗时；数据集规模也不同，这不是严格同题性能对照。最终核心集提取工作链P50/P95为2055/3666毫秒，答案生成969/2320毫秒；盲测3检索759/2786毫秒，个别冷启动Embedding拉长提取P95至约11秒。检索仍受8秒总超时保护。本轮不能声称优化了尾延迟。

保留两项未采用实验：

- 精排补救阈值0.6→0.3，在同一批冻结文本的配对检索重放中，召回88%→96%，精确率96.3%→90.3%，误召回1→3。按“不增加误召回”的既定条件拒绝，默认保留0.6。重放统一重要性/置信度/时间、重建实体、共享热缓存，不能代替完整链质量或延迟比较；没有重新生成答案，也没有产生付费模型调用。
- 增加“保留兼容正负事实”的提取提示未修复Rust事实丢失，并额外保存了附带的“没有主管计划”。该实验目录名为 `delivery`，**代码已撤回**；它不代表交付版本。没有添加按测试人物、城市或问题字符串触发的修复。

## 尚存问题

1. **兼容事实被误当作替换**：先存“主要用Rust写后端”，后说“不以Python为主力”时，模型仍可能选同一个属性键并覆盖前一条。逐来源提取100%不能证明最终状态完整，盲测3的5/6说明仍有丢事实风险。
2. **语义漏召回**：书店采购、长期素食、通勤的部分改写仍被支持门槛拒绝；“Python是我吃饭的家伙吗”这类比喻也未命中。直接降低门槛会污染无关上下文，本轮未采用。
3. **相关但非必需的注入**：问“孟川住哪里做什么”时可能附带姓名桥接；问具体房间号只检索到九楼。后者回答能区分已知楼层与未知房间，但严格检索金标仍记额外条目。路径精简和答案相关性仍需改进。
4. **评估局限**：字符串禁词会把“没说你是飞行员”判成命中“飞行员”，也会把明确承认现预算450元后的条件建议300元判错。未据此改金标或擅自抬高分数；需要后续独立语义审查。第三套质量门槛确实失败，不能仅靠这些评分局限解释。
