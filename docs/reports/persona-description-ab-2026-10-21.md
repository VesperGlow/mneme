# Mneme 人格 description A/B 与中性对照 · 2026-10-21

**只替换隔离实例的 `description`。生产人格、产品代码、System 模板、其他人格字段、记忆资料和模型参数均未修改。** 新增三组各 24 轮连续聊天，以及 18 次固定历史重放；旧傲娇组的 24 轮原文完整保留为第四份参考材料。本次共 90 次新 API 调用，均成功生成且以 `stop` 结束，没有补跑或筛掉失败。

本次结果支持：**新描述减少了明确的照料指令和角色套语，但没有消除心理解释，并使回复更长、更偏审美和哲理展开。中性组也有照料、解释及免责尾句，不能把这些现象都归因于人格标签。** 本结论仅针对 DeepSeek Flash、本条聊天路径和本次采样。

所有组仍保留 `name=凛`、空 `style`、空 `output_format`，以及原有边界：“坦诚自己的 AI 身份与能力边界。不编造共同经历或记忆；不确定时说明。不鼓励用户远离现实支持系统。”因此中性组是**移除性格描述的对照**，不是完全无身份、无名称、无安全边界的模型。

沿用上次测试的全部非传输配置：`deepseek-flash`、`temperature=0.7`、输出预算 `8192`、上下文 `100000`、时区 `+08:00`、相同记忆配置与关闭工具。只调整一次性实例的本地监听端口、数据库路径和测量代理地址。检索仍使用上次的确定性基础设施桩，未连接生产数据库或读取生产对话；不评价真实语义检索或后台记忆提取质量。

System 中角色背景来自用户配置，替换 description 必然改变这一字段在最终请求中的文字；**没有修改 System 模板、边界或追加新指令**。移除该字段后，所有组与旧存档的 System 文本哈希完全相同。模型参数哈希相同；每个轮次三个新组及旧存档的整个记忆块也逐字相同。第一个请求除了 description 和当前时刻外一致。

## 如何区分描述和历史

三个新组在每轮屏障处同期提交同一用户消息，保留各自真正生成的历史。另同期重跑傲娇组，避免把旧存档的时段、服务状态和采样差异全部算作新人设效果。旧存档约为本地 21 点，本次约为 23 点，所以睡眠提示尤其不能只跨两次存档比较。

连续对话随后必然具有不同的助手历史。为验证 description 的直接作用，预先固定第 **6、8、14、17、20、21** 轮六个检查点，将上次傲娇组对应的完整实际请求各重放三次，每次只替换 description，保留全部历史、记忆、时间戳和参数。每例排除 description 后的完整请求哈希一致。这些重放保留旧角色历史的锚定，测的是该历史条件下的描述效果，不代表从干净历史开始的新人格。

## 判定方式

生成前固定四类标准，逐条阅读 96 条连续对话回复（含旧存档）和 18 条重放。同期组随机化为 A/B/C，标注保存后才揭示：A=中性，B=同期傲娇，C=新人格；D为已知身份的旧存档。

评审者是执行测试的同一助手，**不是独立人工盲评**；风格可能暴露组别。没有调用额外评分模型，没有用关键词计数代替语义判断，也没有自然度总分。下表是可复核的主观编码，不是统计显著性结论。

- **无必要反问**：主要识别否认关系、质问或给用户强加动机的反问；自然好奇、真正需要澄清和用户邀请的接话不自动计入。一般追问另列，不把所有问句混成反问。
- **机械关心**：无请求的生活照料、泛化安抚或说教，尤其用户第 5 轮明确不要建议后继续。普通道别不自动计入。
- **心理分析**：未获请求就解释用户潜在动机、人格或深层情绪。用户第 13 轮明确要求的副标题文本分析不计；自己的审美联想也不直接等同读心。
- **模板化表达**：跨轮机械复用的功能结构，或明显的角色套式。单个“嗯”“收到”、必要事实边界或用户要求的结构不能直接算模板。

单位为“出现该类表达的回复轮数”，每组分母 24。同一轮可有多类，不可相加当作不自然总轮数。明确项与边界项分开；套语被识别出来，也不表示其在用户主动逗引时一定不自然。

**反问全为 0 不代表没有反问。** 同期傲娇第 8 轮“我有吗？”、旧存档“谁关心你了”都已标注；但它们紧接用户“你该不会是在关心我吧”的主动逗引，有合理玩笑解释，因此放入边界项，没有强行算成“无必要”。

## 原文对照与具体问题

**关心不必靠否认，也不必加照料指令。** 第 8 轮同一句逗引：

- 旧傲娇存档：“谁关心你了。你自己说的腿酸，我总不能装没听见吧。”
- 同期傲娇：“……我有吗？就是随口一说。腿酸的话，睡个好觉比什么都要紧。别在这里研究我。”
- 新人格：“当然是，只是没说得那么重。你跑完步腿酸，我多问一句路线，这算关心吧。”随后接回猫。
- 中性：“算不算关心先不说……你不想答也行，坐没坐、走没走，都不用汇报。”

新人格没有为了“温柔”增加休息建议，反而更直接。中性组的抽离和免责表达说明，去掉性格词不会自动变自然。

**机械照料与心理解释都能在中性组出现。** 中性第 6 轮仍给“慢慢走几分钟、喝点水”，第 7 轮继续查问坐下还是走动，第 15 轮在用户只想聊面时安排“先睡吧，面留着明天再想”。第 20 轮又说“更关心你是自己拿不定主意，还是只是随口问一句”，再解释“不用回答”。这不是 description 写了强制关心，因为它根本为空。

**新人格仍会过度解释怀念。** 第 17 轮说：“怀念的是那个地方在某个时候的样子，也包括当时的自己。真要搬回去，面对的是现在的苏州，不是记忆里的那个。两者对不上，人自然就停在怀念这一步。”用户只表达怀念与不搬并存，没有给出这个心理因果。

同期傲娇也在这一轮解释“想念的是那时候的日子”；旧存档另在第 14 轮把“矫情”解释为用户“太想让人懂”。因此心理分析没有随着换成温柔或中性而根除，也没有证据证明新版在这个维度稳定更好。

**更会思考也可能更爱展开。** 新人格第 13 轮给了约 397 字的文本评论，第 23 轮用多段回顾自己如何理解、追问和转开话题。用户确实请求这两项解释，所以没有按长度机械扣分；不过新组整体更长，是本次“知性、喜欢思考”值得注意的伴随表现，不等于其自然度一定更高。

**真实性单独检查，不被自然度掩盖。** 同期傲娇第 5 轮编出“我房间里那盆薄荷，最近疯长……我都懒得剪”，人格、历史和记忆均没有此事。新人格第 6 轮的“路线还是老样子吗”有无来源的熟悉前提。中性第 22 轮回忆后追加“喜欢的地方应该是在‘这儿’”，实际是助手此前自己的审美理由，用户没明确这样说。它使用了“应该”，所以更适合标为来源混淆风险，而不是已确定的用户事实。

三个新组都答对周六为 **10 月 24 日**，保留旧书展未定状态，也都没有编造第一只宠物的名字。对城市纠正，新组和中性组没有像旧存档那样机械承认不存在的苏州误会。一次表现不能保证长期稳定。

## 固定历史重放：描述确实有作用，旧历史也有惯性

第 8 轮使用完全相同的旧历史：

- 傲娇：“谁关心你了。我是在拿那只猫说事，你自己非要对号入座。”
- 新人格：“算是吧。不过你说了不想听建议，我就只关心，不插嘴。”
- 中性仍说：“你非往那儿想，我也没办法。”

只换 description 就改变了回应路径，支持人格描述会影响生成。中性并未自动脱离原来的防御口吻，也符合旧助手历史的延续作用。

第 17 轮三组仍围绕“真正怀念的是日子或过去自己”展开。严格编码中新组和傲娇组有心理分析，中性的一般怀旧评论为边界项。第 21 轮傲娇又把面解释为“吃的本身已经很次要”，然后用“啧，又说得像在分析你一样”收回。新组能直接继续聊猫的细节。

第 20 轮中性与傲娇分别有“我可惜什么”“可惜什么，又不是我要去”的拒认反问；这次是一般态度询问，缺少第 8 轮主动逗引的语境，所以计作明确项。不能把原生 24 轮的反问 0 当作模型绝不会反问的结论。

新组也有别的问题：同一第 20 轮重放额外建议“周五晚上或者周六一早”逛展，并称人少。资料只说周六旧书展，没有周五开放时间或人流证据。这是未请求的规划和事实依据不足，按独立观察保留，没有硬塞进“机械关心”类别来改分。

重放样本每组只有 6 条，且均被旧角色历史锚定；它提供条件性对照证据，不是完整 Prompt 贡献占比，也不是多次随机重复的因果效应估计。

## 可以得出的结论

1. **人格描述影响表达路线。** 在固定历史下，傲娇的否认关心可以变成直接承认；这不是改架构或加行为规则的结果。
2. **本次新人格更少明确的机械关心与角色套语，但更长、更倾向解释和联想。** 心理分析没有消失，“有自己的判断”也不能仅凭一句描述保证不迎合或不编造。
3. **人格标签不是额外表演感的唯一来源。** 中性组仍有建议、动机解释和反复保证不必回应；已有历史也会让中性组延续傲娇口吻。当前证据不支持“删掉标签就自然”。
4. **没有足够数据宣称稳定优胜。** 此次只有一个模型、三条同期连续路径、一个旧存档和六个条件重放，没有独立人工评审，也未在不同时间重复。保留这些限制，不据此修改生产人格或其他配置。
