# 人格驱动 Agent：最小迁移与 WebUI 实现

> 后续[真实环境验收](persona-live-acceptance-2026-10-20.md)记录了编译器 v4、可选结构化请求推理参数、媒体协议兼容修复、正式部署及仍未解决的语义问题；以下离线结果只对应其实施阶段。

> 后续扩展已实施：人格现已参与后台事实提取的关注/重要性判断，并增加独立进化记忆、工具反思入口及 WebUI 管理。以下第一阶段设计继续作为人格衍生接口说明；自主学习以 [可追溯进化设计](persona-evolution-design-2026-10-20.md) 为准，不再采用下文早期“压缩调用输出互动观察”的设想。

本设计承接 [代码审计](agent-persona-audit-2026-10-20.md)。用户后来补充的“用户人格为唯一角色设定来源”取代审计初稿中为各场景补写表达习惯的建议。本次实现一个完整的“配置 → 衍生 → 审核/编辑 → 运行时 → 预览/回退”闭环，不增加场景策略路由器、回复概率、人格评分模型或每轮改写调用。

## 数据边界与优先级

| 数据 | 位置 | 权限与作用 |
|---|---|---|
| 原始人格 | 原有 `console.persona` metadata；无覆盖时使用 TOML Persona | 唯一核心角色定义；只有显式设置接口修改 |
| 衍生画像 | 新增 `console.persona_derivation.v1` metadata | 用户原始人格的解释，可人工调整；始终不能覆盖原始人格 |
| 关系、事件、用户事实 | 现有 SQLite memories / sources / conversation_context 与 Neo4j 投影 | 提供真实互动依据，不自动重写核心人格，也不进入人格编译请求 |
| 底层约束 | 现有鉴权、事务、工具权限、来源校验与主系统规则 | 事实、记忆真实性、安全、授权和能力限制不由画像开关决定 |

原始人格的身份、性格、风格、边界和输出格式全部保留。主 Prompt 明确：画像冲突时以原始人格为准；当前明确任务要求可以影响具体表达，不能用画像中的软倾向强制固定格式。事实与工具结果仍由实际数据提供，人物偏好不能伪装为真实肉身经历。

这是一套指令与数据来源约定，不是数学上对模型语义服从的保证。现有来源与权限校验继续执行；本次没有把“模型会遵循画像”当成新的安全防线，也没有宣称解决审计中所有记忆蕴含、工具副作用识别问题。

## 画像结构与缓存

画像包含版本、来源哈希、编译器版本、模型名、更新时间、启用状态和 `needs_review`。六项维度为整体行为、日常闲聊、情绪交流、任务处理、工具使用及记忆表达。**这些名字仅用于展示与组织，运行时不根据它们匹配场景或选择固定模板。**

每项保存：

- `description`：最多 300 字的自然语言倾向；进入运行时画像。
- `basis`：最多 150 字的推导/调整说明，便于人查看。
- `evidence`：原始 Persona 字段及逐字引文；AI 生成结果必须有真实、有效的引文。
- `signals`：最多三个定性参考标签，仅可视化，**不进入运行时决策**，不生成数值概率。
- `locked / edited`：由用户操作决定；模型不能替用户锁定或标记人工编辑。

每次手动保存、生成或回退创建新版本，保留最近五个旧版本。来源哈希只取原始 Persona；更换运行模型不会自动重新编译，因此不同模型可以消费同一份已审核画像。编译器版本改变会令旧画像待更新。单次生成调用复用已有 JSON 客户端与当前配置模型，温度和结构处理沿用现有能力，不追加 DeepSeek 特定参数。

生成器输入只有原始 Persona，不读取聊天、候选记忆、网页或已有画像。随后在应用层合并需保留的人工项，避免让模型自行决定覆盖权限。六项身份唯一、内容大小和来源引文均在 Rust 校验；字面引文校验不等于逻辑蕴含证明，推导质量仍需人审与语义验收。

## 更新、编辑与回退

| 操作 | 行为 |
|---|---|
| 查看页面/启动服务/普通对话 | 读取缓存，不触发编译 |
| 首次生成 | 显式点击后调用一次模型，成功创建版本并生效 |
| 修改原始人格 | 哈希不匹配，画像标记待更新并停止参与生成；数据和历史完整保留 |
| 重新生成 | 保留锁定项和所有人工编辑项，包括未锁定的人工编辑；其余维度可更新 |
| 新人格下保留旧人工项 | 画像进入待核对状态；用户“核对并保存”后才生效 |
| 手动修改 | 提交当前来源哈希及 expected_version；冲突返回 409，不覆盖其他修改 |
| 允许 AI 更新此项 | 明确交还该项更新权，保存后下一次生成可以替换它；单纯解锁不会撤销人工保护 |
| 停用画像 | 下一轮只使用原始人格；保留画像及历史 |
| 回退 | 创建一个新的单调递增版本，内容取所选旧版；旧人格下的版本只能作为待更新/待核对草稿，不能静默生效 |
| 生成失败或内容不合格 | 保留当前画像，展示失败状态 |
| 生成期间编辑或改原始人格 | 提交时再次比较来源与版本，丢弃冲突的生成结果 |
| 页面关闭 | 已开始的生成任务继续；重启中断标记为可重试，不自动追加模型调用 |
| 缓存损坏 | 回退原始人格，展示错误；不阻止 Agent 启动、不自动重生成 |
| 重置 Agent | 默认保留人格与画像；勾选恢复默认人格时同时清理画像缓存 |

生成任务复用现有进程与维护锁，没有新增 worker 服务。状态保存在同一 metadata JSON 中；单进程互斥和版本检查复用现有 settings_lock。聊天开始时复制原始人格与画像状态，本轮压缩、主生成和工具回合使用同一快照；读取遇到不匹配来源时画像自动失效。

## 运行时改动

`chat::context_with_summary` 是正式聊天与预览共用的人格组装入口：原始人格 → 独立的事实/权限约束 → 当前有效画像 → 真实摘要/记忆/历史 → 用户消息。画像作为完整、柔性的解释上下文加入，不由代码挑选“闲聊人格”“技术人格”分支。

本次同时移除摘要和记忆注入时伪造的两条 assistant 确认台词，保留低信任数据标签；计量兼容旧确认消息，但不会把真实历史的第一条助手回复误算成记忆。原先无条件“逐项回应复合问题”收敛为个人事实证据约束。工具正常规则仍要求引用和真实结果；工具收尾不再要求固定汇报结构，而依据人格与用户原始请求表达。浏览器原有鉴权、网络与图片归属限制不变。

本次没有修改工具回合正文拼接、DSML 检测、记忆检索算法或自动提取的来源规则；这些审计发现仍应按报告优先级处理，避免本次 UI/缓存改动扩成全面 Agent 重构。

## WebUI 与接口

Agent 原始人格编辑页下新增“人格衍生”折叠区域，复用现有 details、textarea、按钮、错误提示与响应式布局，无新框架或前端构建依赖。

- 六项画像分别展开，显示 AI/人工标记、锁定、依据与可选参考标签。
- 页面显示空、生成中、已生效、待更新、待核对、停用及失败状态，展示版本、更新时间与生成模型。
- 原始人格保存时更新画像状态；保留当前未保存画像草稿，不静默替换人工内容。
- 可查看实际原始 Persona、画像是否参与、来源哈希、版本和由正式组装入口产生的完整系统提示。
- 最近版本可以展开查看并回退；停用可立即退回原始人格。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / PUT | `/v1/console/persona/derivation` | 查看状态/生效系统提示，或保存编辑与锁定；PUT 含 expected_version、source_hash、enabled、dimensions 和可选 release |
| POST | `/v1/console/persona/derivation/generate` | expected_version、source_hash；`force=false` 命中已生效缓存时不调用模型，UI“重新生成”显式传 true |
| POST | `/v1/console/persona/derivation/rollback` | expected_version、source_hash、target_version |
| POST | `/v1/console/persona/preview` | message、expected_version、source_hash、可选 use_context |

全部接口复用现有 Cookie/Bearer 鉴权与 CSRF 防护。画像按既有 metadata 存储，无新人格表。迁移 0011 只扩展既有模型用量账本的 purpose 枚举，保留所有旧账目并区分 `persona_compile` 和 `persona_preview`。

## 预览与模型调用预算

预览使用已保存、当前有效的原始人格及画像；前端提示保存未提交的原始人格/画像，避免把草稿和真实运行状态混淆。请求携带版本和来源哈希；后端冻结快照，前端不会把旧配置的预览当成新版本结果。

默认预览独立示例，不引入真实对话。勾选后读取已有对话、摘要和真实召回记忆，复用当前预算与来源规则；不触发历史压缩、不写消息、不生成提取任务、不更新记忆访问统计。预览没有可执行工具，不会对网站产生副作用，也不能假称工具操作或记忆管理已完成。预览请求和可选检索仍在原账本计量。

普通聊天不增加模型调用；编译每次显式生成一次，缓存命中为零；预览每次点击一次主生成，勾选上下文时另有现有 CPU 检索开销。第一阶段没有在线人格打分、情绪分类、反思或回复后处理模型；后续自主反思只在有证据且满足触发条件时运行，见进化设计。

## 与关系记忆、逐渐丰富的偏好的后续衔接

本次不放开“所有助手输出都可成为事实记忆”。用户明确陈述的共同约定继续复用 event，近期互动由历史和摘要维持。角色可以在回复中形成有上下文依据的看法，但本次不会自动把一次生成的观点写回核心人格或画像。

如果后续验收证明需要持久的角色学习偏好，最小后续范围是在**现有压缩调用**中输出有来源的互动观察，单独缓存为 `interaction_observations`，而不是增加一轮模型：

1. 区分用户陈述、助手实际表达、双方确认及外部事实，验证 source_id、角色、逐字引用与时间。
2. 助手说过某观点仅证明该轮说过，不能证明肉身经历；一次随机发挥不自动成为稳定偏好。
3. 学习观察始终低于原始人格，用户确认或多次一致互动才能成为待审偏好；修改核心人格后重新核对，不能自动迁移冲突偏好。
4. 不混入现有 `user.*` 自动事实槽位，不因共同话题生成不存在的经历；不要求每轮主动提旧话题。

此段保留第一阶段的衔接考虑。后续已用已有事实提取调用的可选反馈字段实现独立进化记忆，而非压缩输出互动观察；不把助手说过的话当作用户事实，见进化设计。
