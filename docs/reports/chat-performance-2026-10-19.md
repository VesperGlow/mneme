# Mneme 聊天性能验收（2026-10-19）

## 范围与方法

本轮以开始工作时的界面为优化前快照，保留上一轮阅读体验改进，比较本轮前端性能修复。快照位于本地 `artifacts/mneme-ui-perf-before`，JS SHA256 为 `35899e65af13e7c492c8aed32ef6f415f9d116faa219fde8068b09fa7b85d1a7`。它不是旧版 `main` 或旧记忆检索实现。

`scripts/chat-performance.cjs` 在临时 loopback HTTP 服务中运行实际 WebUI，使用明确合成的历史和 SSE，不读取生产配置、凭证或数据库，不调用付费模型。两端使用同一份200轮、400条消息、每轮4次模型请求的数据，保存资源SHA256、原始样本及 nearest-rank P50/P95/P99。

每项120个样本，先排除8个预热样本。普通思考和 Token 面板逐条首次展开，然后折叠；34万字符无空格英文推理另测反复展开/折叠。展开延迟从 DOM click 到两次 animation frame，包含帧等待；它不是操作系统输入到屏幕呈现的硬件延迟。滚动统计为程序滚动期间的 rAF 帧间隔。刷新包含 loopback JSON 请求、解析、DOM 更新及强制布局，每次验证新总量实际显示。定时轮询仅由测试工具改为显式触发，后台异常仅在测试工具中收集。

桌面为1440×1000；移动端为390×844、Chromium CDP 4倍 CPU 降速，另检验320/768/1024px布局。这是浏览器仿真，不等同于真实手机。P99为120个样本的经验分位数，不提供生产环境置信保证；单次首次加载数据单独列出，不能称为首次加载P95/P99。

正式结果生成前采用以下预算：桌面刷新P95≤100ms/P99≤150ms；移动仿真≤250ms/350ms；常规展开/折叠P99≤100ms/150ms；长英文反复展开P99≤150ms/250ms；滚动P99≤33.5ms。还必须通过布局、数字来源标记、键盘操作、展开状态、滚动位置和连续回复完整性检查。

## 修复

- 按消息和轮次建立渲染索引；后台刷新只替换变化的消息，保留其余DOM、展开状态和阅读位置。变化检测包含本轮 Token 汇总，修复仅汇总变化时显示不更新的问题。
- 思考正文、Token 总量详情和单请求详情在展开时生成；每个入口保留原有数据与交互。流式更新按 animation frame 合并，减少每片段全文解析与同步布局，流结束和错误退出前刷新剩余内容。
- 未知非空请求汇总显示“未提供”，零请求的空累计仍显示0；数值超出浏览器精确整数范围时显示 `≈` 并说明显示精度限制。实测/估算来源与后端数值不变。

后端计量与记忆检索逻辑均未修改。用户随后追加的表情包自动描述改英文，仅调整了视觉描述提示词及对应测试夹具。验收期间按当时要求将所有改动保留在工作区；验收后用户已授权提交 main、push 并触发现有镜像构建。没有部署或修改生产记忆。

## 回归

Rust完整回归104项通过、0失败、12项依赖测试按原配置忽略；严格Clippy和rustfmt通过。宿主Python37项通过、10项依赖测试跳过；其中模型容器实际执行原生Tokenizer4项与队列6项，全部通过。Node工具和真实沙箱Chromium15项通过，无跳过。WebUI实际桌面/手机整链通过，覆盖登录、记忆CRUD、XSS、刷新恢复、Token与后端账本一致、流式思考、键盘和设置等。新的详情按需渲染测试等待内容可见后再验证全部字段，没有用固定sleep规避内容检查。日志见本地 `artifacts/chat-regression-*`。

表情包实际PNG/GIF上传、自动理解、搜索、修改、持久化开关、聊天展示、历史重载、移动布局和删除回归也通过。连续流式对话每端各3轮的完整交互时间（含固定测试服务等待）：桌面2023–2039→1039–1073ms；移动仿真7908–8170→1928–2108ms。这里每组仅3次，仅报告范围，不称为P95/P99或真实模型响应时间。

## 追加：表情包自动英文描述

新上传和重新分析使用的视觉提示词明确要求 `description` 用英文、最多120字符，描述可见内容、情绪和适用场景；图中相关文字应简短译成英文。中文短名称沿用现有规则。没有批量修改既有表情包或生产数据。测试检查实际发送的system/user语言约束、英文描述持久化与提示词注入、英文搜索，以及原有异步恢复、失败重试、用量记账和手动修正行为。固定模型服务的英文结果用于契约回归，不冒充真实供应商视觉实测。

## 记忆检索延迟补验

这是另一组组件级对照：早期冻结构建（源码SHA256 `87ed607f...`）及原模型实现，与当前构建及当前模型实现分别运行。它不与上方“本轮UI修改前后”混为一组。使用实际本地Embedding/Reranker、独立临时SQLite及Neo4j，冻结4组已提取事实和36个问题，每组新建应用实例重复6次，共216次/版；统一种子事实重要性、置信度和新鲜度。仅统计默认补救阈值0.6，排除辅助阈值0.3的缓存结果；不运行提取或回答生成，也不调用付费API。
