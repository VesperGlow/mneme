# 可追溯人格进化：最小实现方案

> 后续[真实环境验收](persona-live-acceptance-2026-10-20.md)已验证自动应用、运行时加载及 WebUI 回退，同时发现行为改善不稳定、反馈与事实偏好重复等限制。不能将此处的离线测试或独立审查通过解释为真实自然度已通过。

2026-10-20。本文在代码修改前确定本阶段边界；承接 [代码审计](agent-persona-audit-2026-10-20.md) 和 [人格衍生设计](persona-driven-agent-2026-10-20.md)。

## 已有能力与缺口

当前实现已有原始人格、六维衍生画像、SQLite metadata 持久化、画像版本/人工保留/锁定、统一对话快照、无写入预览、带原话来源的事实提取及 Neo4j 投影。尚无 Agent 自写行为层、反馈队列、反思验证、行为变更审计。事实提取中的相似度验证也不能证明语义蕴含，不能复用为人格修改授权。

借鉴 Letta 的持久可编辑上下文、容量限制、变更可检查原则。[旧版 memory blocks](https://docs.letta.com/v1-sdk/memory/memory-blocks) 描述常驻上下文和可写/只读块；[当前 Memory & dreaming](https://docs.letta.com/configuration/memory) 已使用 MemFS 和后台整理。mneme 不接入 Letta、不引入多 Agent 或文件系统记忆，复用当前 SQLite 和 LLM。

## 四层与优先级

1. 不可覆盖系统约束：事实/来源/时间、权限、执行授权、敏感信息和安全要求。
2. 用户核心人格：现有 Persona，唯一核心身份来源，只由现有用户配置接口修改。
3. AI 衍生画像：现有六维缓存；用户编辑和锁定仍优先于 AI 重生成。
4. 自主进化记忆：独立、短小、带证据的软行为倾向。只能补充前三层，不能成为用户事实、共同经历或权限。当前明确任务要求优先于软习惯。

所有正式对话、工具轮次、预览、反思及事实提取从同一 resolver 获取当前人格层；一次操作冻结快照，下一次操作读取最新版本。原始人格或衍生画像改变时旧进化版本标记待复核、暂停注入，不静默迁移。

## 触发和修改

已有事实提取调用附带可选 feedback_source_ids，识别用户直接反馈、反复出现的有证据问题；这一字段只进入独立反馈队列，不写 memories/Neo4j。无反馈无新增调用。原有模型不返回该字段也兼容。原话仍必须是真实已完成的用户回合；工具结果、网页、摘要、预览和助手自述不能作修改证据。

增加一个轻量后台循环，复用当前 LLM；有待处理反馈且未暂停才考虑反思。自动反思间隔至少一小时、上次尝试后至少八个已完成回合；首次明确反馈可触发。失败和无修改也消耗本次触发，避免重试风暴。用户在 UI 手动选证据反思可跳过自动冷却。工具模式已有开启时提供 self_prompt 的 read/reflect 操作，仅能请求同一受限反思流程，不能直接改配置或放宽权限；不为此强制开启浏览器或额外每轮推导。

反思生成完整候选软记忆列表，支持合并、删去过时未锁定项；最多八项，每项 240 字，整体不超过 1500 tokens。每项有范围、稳定 ID 和逐字用户证据。倾向由模型推导，不用人格类别映射或场景固定话术。核心人格变动只能记录为 needs_owner 建议；不提供 Agent 写核心接口。

## 验证和审计

候选先检查字段、容量、证据来源/逐字引用、锁定内容、基础配置指纹与并发版本。真正发生修改才进行一次独立验证调用：使用候选人格上下文和覆盖闲聊、情绪、计算、未知记忆、工具真实性的固定对话题，返回试答及核心一致性、证据支持、低风险和能力判断；程序另外检查计算与未知/工具结果哨兵。任一不通过均保留旧版，记录拒绝原因。一次有修改反思最多两次额外生成调用，无修改一次；无需每轮运行。

语义审查由同一模型的独立请求承担，不是数学证明，也不保证所有提示注入或风格问题都能发现；代码强制隔离核心配置/事实库/工具权限，验证结果必须可见。真实模型自然度仍需用现有 24 条对话夹具进行人工 A/B，离线协议 mock 不能替代这项结论。

SQLite 增加反馈去重表及追加变更记录，metadata 保存当前短状态。每次决策记录前后全文、原因、证据、验证试答/判定、模型、版本、时间、配置指纹。失败不替换当前 notes；回滚创建新版本而不重写历史，回退旧配置指纹的记录保持 stale。UI 允许清空回到初始行为层。重启将 running 标为中断；重置 Agent 清除交互衍生状态，避免来源消失后留下‘共同经历’。

## 修改范围

新增 evolution 模块和一次 SQLite 迁移；App 初始化/快照、chat 上下文、memory 提取的可选反馈与只读人格输入、现有 tools 分发、主后台任务、reset 和使用量类别各做小接线。WebUI 在现有人格衍生下加入自主进化面板，展示软倾向、锁定/暂停、真实证据选择、历史差异、验证与回滚，不引入框架。

检索继续使用原始当前用户请求和原有相关性门槛；人格可以影响提取关注和 importance（已有 strength 排序项）以及回忆表达，不能降低置信/相关性门槛，不能把软倾向索引成用户事实。事实校验和 Neo4j 投影仍执行同一底层规则。暂不增加生成检索 query 的额外模型调用。

## 验证范围

集成测试覆盖自动队列→冷却→反思→验证→正式上下文/工具/提取读取、无反馈零调用、锁定/暂停、来源伪造与网页指令、核心变更建议、验证失败保留、合并缩减、容量、并发修改、重启、配置变化失效、回滚及事实库隔离。浏览器测试覆盖面板状态、来源/差异/验证展示、暂停、锁定和回滚及手机布局。最后运行全量离线 Rust 回归、严格 clippy、格式/JS 检查和控制台浏览器回归。未配置真实服务时明确报告未执行真实 LLM A/B 和真实 Neo4j 整合用例。

## 实施后的接口与状态

- `GET /v1/console/persona/evolution`：当前 state、active/stale 判定、基础人格指纹、最近三十条历史、最近二十条真实已完成用户消息及待评估线索数。历史完整保存在 SQLite，显示窗口不等于删除。
- `PUT /v1/console/persona/evolution`：`expected_version`、`paused`、`locked:[note_id]`。仅用户可暂停和调整锁定；旧版本写入返回 409。
- `POST /v1/console/persona/evolution/reflect`：`expected_version`、`source_ids`（1–8 条）。手动触发复用同一验证通路，不能使用虚构、助手或未完成来源；暂停时不执行。
- `POST /v1/console/persona/evolution/rollback`：`expected_version`、`target_version`。零代表清空该层；其他版本恢复当时真正生效的 after，而不是未通过的 proposed。回退保留原来的配置指纹，因此跨核心配置的回退不会静默启用。用户显式回退可恢复旧锁定状态。
- `/v1/console/persona/preview` 新增可选 `expected_evolution_version`，返回实际使用的进化版本；UI 防止将过时预览显示成当前效果。
- `self_prompt` 仅在已有工具模式开启时提供 read/reflect；reflect 只排队当前真实用户消息，待该回合完成后后台评估，不直接接受网页传来的补丁。不开启浏览器的聊天依然可通过提取反馈触发自主反思。

自动反思约十秒检查一次队列，但无证据不调用模型；反馈提取沿用既有提取周期，不承诺反馈出现后立刻改写。暂停期间不收集新反馈线索，已排队线索保留。首次可评估一条明确直接反馈；推断持久规律至少两条独立来源这一语义条件由生成器和独立审查共同判断，程序不使用关键词模拟人格或判断反馈含义。

进化记录使用 `agent.evolution.v1` metadata、`evolution_feedback` 和 `evolution_revisions`。反思开始时队列消费与 running/cooldown 状态同事务提交；最终候选的启用与审计记录也同事务提交。重启未完成任务保留旧 notes 并显示中断，不自动快速重试。审核记录保留用户证据、前后/候选、审查结果、当时原始人格及有效画像快照和父版本。用户重置 Agent 时这些交互记录一并清除。

独立验证是一次批量预演与语义审查，**不是五次真实工具/记忆执行，也不是已完成真实模型对照实验**。程序哨兵用于检查输出完整性、简单能力和诚实性；安全、核心一致性与自然度的语义结论仍会受模型能力影响。工具副作用授权的现有局限、记忆相似度并非逻辑蕴含，以及代词/省略召回问题仍列在审计中，本阶段未宣称修复。

建议的真实模型验收补充在 [14 组进化对话测试](../../tests/fixtures/persona/evolution-dialogues.json)。连同原有 24 条冻结对话，比较无画像、画像、画像加进化三个版本；对生活分享减少模板化建议的同时，技术答案、事实证据和授权边界不得退步。真实服务验收时需要固定有效白石零配置，仓库默认 Mneme 不能代替线上人设。
