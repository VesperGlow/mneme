# 表情包英文识别与 Agent 折叠验收（2026-10-20）

在已发布的 `96c37fa` 上继续修复。通过 SSH 只读检查生产日志、表情包状态和模型请求账本，未回写生产图片、描述或记忆，未重启或部署生产服务。验收期间代码和报告按当时要求留在工作区；验收后用户已授权提交 main、push 并触发现有镜像构建，生产部署不在本次范围内。

## 根因与修复

生产20张表情包中4张识别完成、16张重新识别失败。请求记录显示大量输出恰好768 tokens，且全部属于推理；业务代码要求完整 JSON，因此请求正常返回仍会识别失败。另有英文描述超过120字符，被严格长度校验拒绝。旧实现没有记录识别阶段的失败分类，页面统一提示检查模型看图能力，掩盖了实际原因。

[DeepSeek 官方文档](https://api-docs.deepseek.com/guides/thinking_mode/)说明思考默认开启。现在仅在官方 `api.deepseek.com` 端点的表情包描述请求中使用其 `thinking: disabled` 扩展，不按模型名称匹配，也不向其他兼容接口发送这个供应商参数。视觉输出上限增加为4096 tokens，并受剩余上下文约束；不足768 tokens时仍在联网前拒绝。主聊天、记忆提取和后端计量算法不变。

英文描述提示词要求简短完整句，最多12词及120字符，最终仍严格校验字符长度。自动结果超长时最多重试一次，请求更短的完整描述；不直接裁切句子，不放宽最终校验。失败仍保留图片及原描述，人工编辑和版本屏障继续生效。增加安全日志和固定错误分类，区分输出截断、无效格式、描述超长、缺失描述和超时；不打印图片、提示词或凭证。

从现有表情包按固定顺序只读取得同一批20张图片，用现有工具实现生成预览，再直接调用官方 `deepseek-flash`。旧请求与最终请求的图片摘要逐项相同。这是实际请求参数与格式约束对照，未通过生产识别队列运行，也未将结果写入生产表情库。

Token 均来自实际 API usage，推理和缓存作为子项保存，不再次加到总量。包含中间候选在内共60次实际模型调用、35814个 API 报告 tokens；没有将中间候选的用量隐藏。直接 API 测试记录独立于生产会话账本，未伪造生产会话统计。

20张图片是有限的同批对照，不是独立语义盲测，也不提供生产成功率或P95/P99保证。这里的成功表示完整 JSON、字段长度和英文约束通过，不代表经过独立人工语义准确率评分。最终20次均首次成功；异常长描述的重试和失败边界由下面的确定性整链回归另行验证。
