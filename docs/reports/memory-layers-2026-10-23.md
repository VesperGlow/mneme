# Mneme 增量记忆与分层存储验证

日期：2026-10-23。

## 检查结论与根因

现有系统已经包含 SQLite 原始对话、增量 Token 水位、持久化提取/投影队列、Neo4j 向量与全文索引、RRF 和 Reranker，无需增加服务。Token 累计与空闲排队链路通过现有及新增测试，未发现需要替换调度架构的问题。

可以从代码和确定性回放验证的丢失机制：

- 原提示词明确排除闲聊、短暂心情和一次性感想，只接纳稳定事实、长期偏好和重要经历。“终末地的剧情也太 ML 了”因此容易得到空候选。
- 重要性 0.4、置信度 0.7 原本作为统一存储门槛，具体但低评分的日常表达也被丢弃。
- 所有候选入库前均依赖 Embedding 证据校验；已有记忆的提取上下文同样强依赖 Embedding。依赖故障可能阻断整批写入。
- 缺少持久化候选和压缩历史，用户难以区分“尚未触发”“模型没有输出”“被过滤”“等待重试”和“已经保存但未索引”。

这些是机制层面的根因；本次没有连接用户运行中的生产数据库，不能据此断言某个部署发生过哪一种服务故障。

## 实现

1. 保留约 2048 个新增用户/助手原文 Token 触发、120 秒最长等待、独立于上下文摘要的增量水位。空闲时后台主动调度，不要求再发一条消息。
2. 提取改为高召回的情景拆分，覆盖具体事实、观点、兴趣、情绪和互动细节；存储不再按重要性过滤。纯无内容应答仍可跳过，来源验证和既有敏感/遗忘边界保留。
3. 区分 `episodic` / `long_term` 和 `user_quote` / `explicit_fact` / `inference`。模糊断言降为原话；推断增加未验证标记、置信度上限 0.6，不能覆盖明确事实。用户原话的置信度表示引用确实存在，不表示其含义已获验证。
4. 原话情景先提交 SQLite，现有投影队列随后使用同一 Embedding 服务写入 Neo4j。已有记忆上下文在 CPU 故障时可用 SQLite 关键词补检。混合批次的事实校验失败时，已独立取证的原话仍可保存，其余来源重试。
5. 精确重复候选合并；重复表达补充来源，单一来源重试不制造独立确认。偏好至少需要两个独立轮次的明确支持，符合长期门槛后才晋升。矛盾信息沿用现有属性纠正、历史版本、时序和遗忘屏障。
6. 情景最长 30 天、7 天半衰期、最多 256 条有效工作集。重复来源可刷新观察时间，检索不会延长寿命。每小时整合明确偏好证据并维护数量边界；图谱清理走持久队列。原始对话、来源及审计继续保留，因此工作集有界不等于物理数据不再增长。
7. 复用混合检索和严格 Reranker 筛选；低于绝对/相对或语义门槛的候选不进入上下文。精排不可用也不把 RRF 排名当作相关性。修正了 WebUI 原先关于精排失败回退行为的错误文案。
8. 新迁移 `0015_memory_layers.sql` 保存层级、证据类型、逐来源置信度和显式期限，修订快照同步保存新字段。Neo4j 投影补充层级、证据、置信度及时间元数据，SQLite 继续作为事实与来源的权威存储。
9. 新增鉴权接口 `/v1/console/extraction`。WebUI 原有后台队列展示压缩历史、Token 水位、分层数量、整合结果、候选、拒绝原因、存储 ID 和索引进度；详情显示逐条证据。历史最多 200 次，决策最多 1000 条；计数独立于截断后的决策轨迹保存。成功历史与入库、处理回执和任务确认同事务提交。

上述端到端测试使用真实 Rust HTTP/SQLite 路径及确定性 LLM、Embedding、Reranker、Neo4j HTTP 替身；验证的是链路和策略契约，不是线上 LLM 语义准确率。真实模型、图谱及付费提供商相关测试保持原有跳过条件。本次未调用付费 API，也未修改线上部署。
